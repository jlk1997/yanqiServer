# 研企通 · 前沿体验超越（M28）

> 大白话：用户要的是「交付心态做到像 200%」，不是把健康检查数字写成 200%。本波对标成熟商业 B2B + 政企服务大厅，把多角色壳从「能进不同页面」升级成「真像能卖的产品」。

## 对标看了啥（模式，不抄界面）

| 参考 | 可抄的模式 | 我们要超越的点 |
|------|------------|----------------|
| 南京成果供需对接 / 深圳线上工研院 | 供需大厅分角色；首页突出「发成果 / 发需求」；表单减字段；智能匹配入口 | 按角色工作台拆开，不只一个大厅堆模块 |
| 区域科创小程序（需求摘星 → 成果认领 → 活动） | **主链路优先于功能清单**；状态可追踪 | 企业/科研/经纪人各一条主链路，首页不讲别的 |
| 飞书 / 钉钉工作台 | 「今天待办」优先；角色化；双工作台（业务前台 vs 管理后台） | 运营深色后台 vs 业务浅色前台彻底分开 |
| 政企服务大厅 | 统一入口、办件状态可视、观察看板、信任与合规提示 | 园区壳只看汇总/案例/政策位，不进采洗配联 |

共性结论：

1. **角色首页 = 少数主业**，不是功能瀑布。
2. **渐进披露**：进阶能力进「更多」。
3. **状态驱动列表**：管道/看板比无限滚动更重要。
4. **空状态要有下一步**，别留白骂用户。
5. **G/C 观察员**看数与案例，不碰运营脏活。

## 对照现状的缺口（M27 之后）

- 壳分了，但视觉仍像「浅色皮肤的内部工具」：间距、字号、主 CTA、信任条不统一。
- 企业/科研首页缺 **状态管道**（发了几条、匹配几条、跟进到哪）。
- 经纪人 SLA 是 JSON 黑盒，不像「按紧急度排队 + 一键下一步」。
- 园区 `work-park` 仍是占位文案，没有观察看板。
- 顶栏没有「组织 · 身份 · 切演示号」统一控件。
- 移动端断点只做了侧栏横排，空状态/管道未适配。

## 本波改什么（已按此落地）

1. **轻量设计系统**（CSS token）：浅色商业感、主 CTA、卡片、管道、空状态、信任条；端用户不再像运营黑屏。
2. **各角色首页**：今天三件事 + 状态管道 + 空状态下一步；减少滚动噪音。
3. **企业**：发需求 → 匹配收件箱 → 跟进状态，文案人话化；可请求联系/确认意向。
4. **科研**：上架能力/成果 → 企业意向 → 回应（有意向/婉拒）。
5. **经纪人**：按 SLA 紧急度排队，一键「建议下一步」。
6. **园区/政府观察**：公开向汇总看板（统计 / 案例 / 政策位），无运营侧栏。
7. **运营**：保留火力，默认「今天待办」；次要分组折叠；顶栏标明身份。
8. **横切**：统一顶栏（组织/角色/切演示）、基础 a11y、工作壳移动断点。
9. **工作台 API**：`/workbench/home` 按壳返回 pipeline、empty、nextStep、parkObserve。

## 刻意 backlog（不假装做完）

- 园区独立审批与政策库 CMS（本波政策位为静态引导）
- 运营台微前端拆分
- 工作台组件可拖拽自定义（飞书级）
- 原生 App / 小程序
- 多语言与白标视觉完整主题包

## 诚实成功标准

- 五个演示号 30 秒内能说出「我今天点哪三下」。
- 园区号进观察壳，看不见采洗配联。
- `npm run gate` 绿；波次 `M28-ux-surpass`。
- **综合诚实约 91%**：体验与角色信息架构抬升；支付仍弱；「200%」是交付心态，不是健康检查字段。

## 「交付心态 200%」vs 测量维度

| | 含义 |
|--|------|
| 交付心态 200% | 对标顶尖再加一档才谈交付；长期迭代，不把半成品当完 |
| 测量综合 ~91% | 能力/安全/匹配/体验加权诚实分；支付、园区审批、自定义工作台仍欠 |

下一波建议：园区政策与案例 CMS + 企业侧「匹配解释一页纸」+ 支付最小闭环试点。

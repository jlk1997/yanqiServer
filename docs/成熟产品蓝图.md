# 研企通 · 成熟产品蓝图

面向中国高校实验室、科研院所与企业的科研项目/成果转化对接平台。语言与交互全部用大白话中文。前期可全站免费，但套餐、配额、功能开关必须先建好，方便以后收费。

## 1. 产品愿景

把「实验室能做什么 / 已经做出什么」和「企业要解决什么」自动对上，并让运营和机构自己跟进。前期靠合法公开数据与授权数据把双边档案跑起来；后期销售与邀请把真实客户拉上平台。

## 2. 用户与角色

| 角色 | 谁 | 能干什么 |
|------|----|----------|
| admin | 平台超管 | 用户、套餐、调度、全局配置、审计 |
| operator | 运营 / BD | 采集任务、匹配复核、线索人审发信、作战包 |
| org_user | 高校/企业用户 | 认领组织、维护三张卡、看推荐与报告、发对接意向 |
| guest | 访客 | 浏览公开成果/需求摘要、注册申请 |

## 3. 产品面（必须齐）

### 3.1 公开门户（B 端）
- 首页：产品说明、数据概况、典型匹配案例（脱敏）
- 成果广场 / 需求广场（公开摘要）
- 注册 / 登录 / 认领组织
- 机构工作台：我的能力/成果/需求、推荐匹配、分析报告、通知
- 邀请落地页（已有，继续加强）

### 3.2 运营中台（已有运维台升级）
- 总览、组织、三张卡、匹配、线索、任务、审计
- 新增：用户角色、套餐配额、定时爬取、数据质检、报告生成、通知广播

### 3.3 AI 与匹配
- 可解释打分（规则 + 向量）
- 组织/需求/匹配「分析报告」一键生成（中文 Markdown/HTML）
- 运营可改理由、驳回、反馈标签（为后续学习排序留口）

### 3.4 双边长期采集
- OpenAlex 高校批采（定时）
- 企业 CSV / 授权 API 导入（定时或手动）
- 公开页抓取 Worker（合规白名单域名）
- JobLog + CrawlSchedule + 失败重试 + 质检分

### 3.5 触达与 CRM
- 线索：草稿 → 人审 → 发送（SMTP/dry-run）
- 站内通知中心
- 销售作战包导出
- 中期：Chatwoot / AiToEarn

### 3.6 商业化骨架（可先免费）
- Plan：免费版 / 机构版 / 运营版（名称可改）
- 配额：月匹配次数、月采集任务、报告份数、席位数
- FeatureFlag：按套餐开功能
- 支付：桩接口（createCheckout → stub success），不接真支付也可演示升级

## 4. 核心链路（成熟版）

采集调度 → 质检入库成卡 → 匹配打分 → 生成分析报告 → 运营复核 → 通知机构/发信 → 机构自助完善 → 再次匹配闭环

## 5. 分期（成熟产品）

| 阶段 | 主题 | 完成标准 |
|------|------|----------|
| M0 | 内部运维可日用 | 已完成（第三波） |
| M1 | 角色权限 + 商业骨架 + 定时任务 + 分析报告 API | 本波 |
| M2 | 完整双端门户与机构工作台 | **本波加深完成（自助三张卡/认领）** |
| M3 | 数据质检流水线 + 反馈学习 + 站内通知产品化 | **本波主完成（仍可加深看板）** |
| M4 | Chatwoot/AiToEarn、pgvector SQL、多租户 | **已启动桩（tenantId/集成配置）** |
| M5 | 经纪人协作、白标、真支付 | 后续 |

## 6. 技术原则

- NestJS + Prisma + Postgres；队列 BullMQ/进程回退；定时 node-cron
- 中文 UX；扩展字段 JSON；不绑单校流程
- 合规：禁 CNKI 灰爬；邮件人审；AGPL 不进多租户核

## 7. 成功指标（内部）

- 冷启动：≥50 组织、≥200 成果、≥30 需求后匹配有稳定 Top
- 运营：人审通过到触达 < 1 个工作日
- 产品：机构用户可自助改卡并看到推荐
- 商业：免费档配额可配置，升级路径可演示
